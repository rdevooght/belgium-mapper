# `nis_entities.json`

Generated by `data_preprocessing/preprocess.py` (marimo notebook) from `TU_COM_REFNIS.csv`.
It is a **flat map of geographic entities indexed by NIS code**, and the canonical source of truth:
each entity appears once. The hierarchy region > province > district > municipality is not nested,
it is recovered with `parentNis` / `childrenNis`.

```json
{
  "entities": {
    "02000": {
      "nis": "02000",
      "type": "region",
      "name": "Region name",
      "alternateNames": ["region name", "alternative name"],
      "parentNis": null,
      "childrenNis": ["10000"]
    },
    "10000": {
      "nis": "10000",
      "type": "province",
      "name": "Province name",
      "alternateNames": ["province name", "alternative name"],
      "parentNis": "02000",
      "childrenNis": ["11000"]
    },
    "11000": {
      "nis": "11000",
      "type": "district",
      "name": "District name",
      "alternateNames": ["district name", "alternative name"],
      "parentNis": "10000",
      "childrenNis": ["11001"]
    },
    "11001": {
      "nis": "11001",
      "type": "municipality",
      "name": "Municipality name",
      "alternateNames": ["municipality name", "alternative name"],
      "parentNis": "11000",
      "childrenNis": []
    }
  }
}
```

## Fields

- `nis`: unique NIS code, always a **string** of 5 digits (leading zeroes kept, e.g. `"02000"`). Same as the key.
- `type`: `"region"`, `"province"`, `"district"` or `"municipality"`.
- `name`: canonical name, in the main language of the area (as in the source CSV).
- `alternateNames`: normalised names (lowercase, trimmed, no accents, straight apostrophes) in the 3 national languages, with and without the level qualifier.
- `parentNis`: NIS of the parent entity, `null` for regions.
- `childrenNis`: NIS codes of the children, sorted; empty for municipalities.

## Notes

- Brussels has no province: its district (`21000`) has the region (`04000`) as parent. There is no fictional province,
  since it would need the same NIS as the region.
- The file holds no lookup index (e.g. name -> NIS): those are built at runtime in JavaScript.
- Entities are sorted by NIS. Note that JavaScript iterates integer-like keys (`"10000"`) before the others (`"02000"`),
  so do not rely on key order.
- Integrity checks (unique NIS, existing and consistent parents / children, string NIS) run when the file is generated
  and in `tests/nis_entities.test.mjs`.
